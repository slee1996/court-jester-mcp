01

The model writes plausible code. The plausible part is the problem.

AI agents are good at sounding finished. They hit the marks. The diff reads clean. The tests they wrote for themselves pass. Then the edit lands on main with a subtle off-by-one, a silent nullish-string leak, a roundtrip that drops data on Unicode.

Court Jester runs the moment the edit is written. It parses the changed file, synthesizes a fuzz harness from the AST, runs it in a sandbox, and stops being polite when something contradicts itself. No transport layer. No plugin. One binary that shells out like any other CLI.

Not a CI replacement. CI still gets the last word. Court Jester gets the first one — while the agent is still in the loop and a fix is cheap.

03

What it catches.

Crashes and contract violations. Treated the same: both fail the run, both come back with a concrete input.

Runtime crashes
TypeError, AttributeError, KeyError, IndexError, RecursionError, MemoryError, ValueError, ZeroDivisionError, UnicodeError, RangeError, ReferenceError, URIError, stack overflow.
Return-type mismatches
the declared shape says one thing, the runtime produces another.
Symmetry & roundtrip
decode(encode(x)) == x fails for an inferable encode/decode pair. Usually a Unicode edge case the model didn’t reach for.
Nullish-string leaks
None, undefined, or null makes it into a user-visible string. Classic agent blindspot.
Idempotency & boundedness
a function that should be stable under repetition drifts. A bounded value escapes its bound.
Comparator violations
a sort key that isn’t transitive. Works on the happy path, corrupts the order elsewhere.
Blank outputs
the function runs clean and returns "". The tests don’t check.

04

Watch the loop get less gullible.

Twenty-four seconds: visible tests pass, Court Jester finds the edge case, the agent gets a concrete repro, and the rerun earns its exit.

Install

curl -fsSL https://raw.githubusercontent.com/slee1996/court-jester-mcp/main/install.sh | sh

Run it after every agent edit

court-jester verify \
  --file <changed-file> \
  --language <python|typescript> \
  --project-dir .

After every code change, run `court-jester verify`.
Repair verdict: fail, investigate verdict: inconclusive, and ship only verdict: pass.
